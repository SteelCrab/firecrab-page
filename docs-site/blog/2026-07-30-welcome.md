FireCrab의 문서와 개발 기록을 남길 공간을 만들었습니다. 랜딩 페이지와 같은 저장소,
같은 도메인에서 `/docs` 경로로 서비스합니다.

{/* truncate */}

## 왜 같은 저장소인가

문서를 별도 저장소로 분리하면 랜딩 페이지의 링크와 문서 배포 시점이 어긋나기 쉽습니다.
지금은 한 사람이 양쪽을 모두 관리하고 있어서, 랜딩 문구 수정과 문서 갱신을 하나의 커밋으로
처리할 수 있는 편이 훨씬 낫다고 판단했습니다. 같은 도메인을 쓰기 때문에 검색 엔진 입장에서도
문서가 별개 사이트로 취급되지 않습니다.

빌드는 Vercel 단일 프로젝트에서 랜딩(Vite)과 문서(Docusaurus)를 순서대로 돌린 뒤
문서 산출물을 `dist/docs`로 옮기는 방식입니다. 문서 빌드가 길어지면 그때 배포만 분리하면 되고,
저장소 구조는 그대로 두어도 됩니다.

## 앞으로 쓸 것

- 설치와 초기 설정 가이드
- REST API 레퍼런스
- Firecracker 연동 과정에서 부딪힌 문제와 해결 기록

문서는 [소개 문서](/docs)에서 시작하시면 됩니다.
